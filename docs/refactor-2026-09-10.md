# 2026-09-10：Worker 组合与 Agent 基础重构

> 历史记录：本文的顶层 node.ts、worker.ts、agent/ 和 AGENT.* 已被 Worker 归属结构替代。当前实现以 [架构](architecture.md) 和 [开发指南](getting-started.md) 为准。

## 对架构的理解

可扩容的单位是 Worker：副本包含一组 Node、内部执行图与私有资源。Node 表达能力，名字不决定部署位置；Graph 表达能力之间的依赖。多个 Worker 的通信通过 Runtime 提供请求/响应和独立事件服务，本地可直调，跨服务器由适配器传输。

Agent 能力属于 Node：模型推理、工具、MCP、Skill 的选择与执行不应变成 Runtime 的调度分支。Runtime 负责统一提供环境、模型配置、Provider 注册与权限服务。

## 本次改动

| 原问题 | 调整 |
| --- | --- |
| Worker.type 从 Node 前缀推导，混合能力被禁止 | Worker.type 改为独立部署角色；保留 Node 输入输出类型约束 |
| Graph 只有 Runtime 全局执行范围 | 增加 ctx.run，绑定当前 Worker 副本；ctx.invoke 保留跨 Worker 语义 |
| Worker 的每个 Node 都成为公开路由能力 | 增加 expose，区分内部 Node 和外部入口 |
| 副本没有并发参数或释放入口 | 增加 concurrency、dispose、handle/runtime.close；满载失败而非无界排队 |
| 通信只有测试适配器 | 增加真实 HTTP client/handler、认证、协议头、输入边界和大小/超时限制 |
| 缺少环境、模型和权限装配 | 增加显式 env 解析、.env.example、RuntimeServices、Provider 与 Sandbox 模块 |
| Agent 功能只能由实验代码从头构造 | 提供四个 AGENT Node、工具循环、MCP 注册、Skill 管理 |
| 文档缺少地图，历史设计易被当作现状 | 增加 docs/README，重写中英文入口及当前架构指南 |

## 兼容与限制

原 18 个 Node 数据契约保持 v1.0，现有测试继续验证契约与执行行为。旧 Worker 不提供 expose 时公开所有实现，原类型前缀相同的定义仍可使用。WorkerContext 新增服务和内部 Graph API；手工构造 Context 的消费者需要补齐字段。

仍保持单包、零第三方运行时依赖。没有加入自动部署控制器、分布式状态机、持久化队列、工作流恢复或通用插件扫描。扩容由 register/registerRemote 驱动；HTTP 超时不取消远端副作用，权限服务不冒充 OS 沙箱；MCP SDK 连接和外部客户端生命周期归应用负责。

## 验证

测试覆盖固定契约、原有路由/Graph/Event/Artifact、混合命名空间的 Worker 内部 Graph、副本资源与并发/回收、真实 loopback HTTP、配置及文件权限、模型消息转换、工具循环、MCP 分页/卸载与 Skill 权限。测试使用离线 Provider 与 MCP 客户端替身，没有执行计费模型调用或真实远程 MCP 集成测试。原示例工程已移除，examples/ 保持空目录占位，后续承载基于 npm 包的 Agent 例子。

## 工程减重补充

删除 `src/nodes/` 中未参与执行的抽象空类，将 `src/node/`、`src/worker/` 分别收敛为 `node.ts`、`worker.ts`。删除旧类导出、命名空间到 Worker 的辅助类型与无效泛型；基础契约类型合并到一个入口，Graph 构建和执行放在同一文件。

`@ditto/core/nodes` 与历史 `BaseNode`/`InferNode` 等类不再提供，已有继承代码迁移到函数 handler 或 defineNode。原 18 个业务输入输出仍与评审基线逐项检查，测试基线也只保留数据契约。

Agent 内部 Graph 在模块初始化时构建一次，调用时复用；路由改为单次遍历，不引入新的缓存或索引系统。保留能力组合、内部 Graph、副本资源、HTTP 和权限语义。
